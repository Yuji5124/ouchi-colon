# Colon BLE連携 v34

2026-11-09。使用時の経路を次に統一する。

```text
スマホのColon操作画面 → BLE → AtomS3 → AE-DRV8835-S → 左右モーター
```

初回はHTTPSからアプリを読み込む。対応ファームウェアが未搭載の場合だけPCのUSB書き込みが別途必要。使用中のAtom接続に家庭内Wi-Fi、Atomのアクセスポイント、PC中継サーバー、ローカル証明書は使用しない。

別チャット「Ouchi Colon外装アプリ」で作成された `ouchi-colon-motor-test` の次のコードを `src/robot/ble-core/` に取り込んだ。

- 元コミット: `ee2474bea4ab66ea45590c4140e9e1a7f678cb2c`

- 通信のロジックを再利用。`transport.ts` の非対応ブラウザーの案内だけをBluefyを含む表現に変更。
- 元のフォルダとファームウェアは編集していない。校正パターンの保存・上書き・リセットは行わない。

接続するのは既存の **colon-motor-1.8.0 / patternsVersion 6**。kabayan教材の「初回USB、運用時BLE」という接続方式を採用し、通信内容はOuchiColon専用20バイトプロトコルを使用する。汎用Notif表示ファームウェアとの互換性は仮定しない。

## iPhone 11で開く

1. iPhoneのBluetoothを有効にする。
2. Bluefy等、Web Bluetoothを公開する対応ブラウザーで、`https://yuji5124.github.io/ouchi-colon/phone.html?v=34` を開く。Safariでは実機接続を無効にして理由を表示する。
3. 「接続・操作」の動作先はBLEが初期選択される。「動作先に接続」を押し、機器選択画面でAtomS3を選ぶ。ファームウェア・起動ID・停止状態を読み取る。接続だけでは動かない。
4. 初期モードは動作OFF。「ラジコン」または「返答と連動」を選ぶ。
5. 配線・物理スイッチ・浮かせた状態・電源と電流条件を確認し、「この機体の電源・100%出力条件を確認した」をチェックする。
6. 「次の1回を許可」でブラウザー内の許可を与える。この操作では本体へARMを送らず、本体が駆動中であるという表示もしない。
7. ラジコンは方向ボタンを押す。返答連動はTOHOKU音声を準備し、次の喜び・驚きの返答の再生開始に短い動作を行う。必要に応じ「文字で会話して連動を確認」も利用できる。

BluefyのWeb Bluetooth対応についての開発元説明:
https://apps.apple.com/app/id1492822055

ホーム画面から起動した場合もBLE APIを再判定し、検出できなければ接続しない。Bluefy内での読み込みと保存を基本とする。APIの有無を検出できても実機動作の確認とは区別する。

## 既存1.8.0の出力条件

**100%・1000Hz固定**。出力を15%と表示しながら100%に変換する処理は入れていない。速度スライダーを100%固定表示にし、1回100/300/500msの時間で動作を調整する。従来版の直接操作は即時100%出力で、Wi-Fi診断版のソフトスタートは適用しない。

このプロファイルではWi-Fi診断版の「VM 1.5V以下」という入力欄は適用しない。実機の電源条件は従来BLE機体で確認した条件を使用し、電圧の自動変更や適合判定は行わない。`powerQualified` は本体の報告値を維持し、動いたことや確認チェックを根拠にtrueへ変更しない。

左右の向きは既存1.8.0の修正済み旋回規則に合わせた。反転チェックは使用中の機体に合わせ、浮かせた状態で確認する。校正済みの角度を使ったA01〜A17の一括実行は今回のUIには追加していない。旋回角度の一致は保証しない。

## 停止・心拍・再接続

- 既存350msの心拍タイムアウトを維持。40msごとの通信スケジューラーから心拍を優先し、定期読取りが心拍を妨げにくいようにする。
- 指を離す・キーを離す・停止・非常停止・ページ非表示・接続切れで許可と継続動作を取り消す。再接続・非常停止解除は自動再許可しない。
- 機器選択中の一時的なフォーカス移動では、駆動許可がない接続処理を誤って取り消さない。実際のページ非表示・退出は接続解除する。
- 停止が確認できなければ接続を解除する。BLEの通信遅延があるため、ソフトウェア停止だけを物理的な即時停止の保証にはしない。
- 短いパルスが最初の読戻し前に正常終了した場合、起動ID・nonceの更新・pulse-limit・出力ゼロを確認して、通信失敗と区別する。

## 初回保存とインターネット接続

「画面をオフライン用に保存」は、実際に配信するHTML、JS/CSS、依存モジュール、顔PNGを現在の版のキャッシュへ保存する。保存APIやService Workerが使えない環境、保存に失敗した場合は成功表示にしない。

保存後は、そのブラウザーでネットを切った再起動を実機確認する。ブラウザーによるデータ削除や容量制限があり、永久保存を保証しない。

TOHOKUモデルは別途「TOHOKU準備」で読み込む。音声認識はオンライン利用が前提で、BLE操作とは別に扱う。Wi-Fiを切っても携帯回線を使う構成は可能だが、Bluefyでの音声認識API提供と音声・BLE同時動作は未検証。APIがない場合は文字入力を使用する。完全オフラインの音声会話が完成したとは扱わない。
