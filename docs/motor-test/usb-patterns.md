# USB書込み・パターン保存（現在の1.8.0）

PC Chrome / EdgeでUSBから走行プログラム1.8.0を書き込み、通常起動後はBLEのColon-Motor-Testへ接続します。USBを選択しただけでは書き込みません。書込み中はモーター電源VMと外付け回路を外します。既存ファームの置換と復元方法はUSB欄で確認します。iPhone Safariは実機USB書込み・BLE操作に対応していません。

- Atomへ保存する基本校正値は10個（形式6）。No.1=前進100%・1秒、No.2=後進100%・1秒、No.3〜8=左右15/30/45°、No.9=右90°、No.10=左90°です。
- 左右共通の初期時間は15°=2000ms、30°=4000ms、45°=6000ms、90°=12000ms。時間は50〜12000msで調整し、0msは未設定で実行できません。片側の変更は反対側にも反映されます。
- 「このPCに保存」はブラウザのみ。「Atomへパターンを書き込む」はBLEでNVSへ保存し、読戻しを確認します。未転送の編集値はAtomへ反映されません。
- A01〜A17は10個の基本校正値を用いるブラウザ側の複合動作です。17個すべてをAtom内で単独実行する仕様ではありません。
- 接続するだけでは動かず、操作ごとの許可チェックは不要です。古いnotif / notifnano / v10のファームには専用BLEサービスがありません。

# USB書込み・12パターン・OuchiColon連動

この版はAtomS3 C123用 `colon-motor-1.1.0` の信号試験です。実機書込み・通電試験は開発時に実行していません。電源適合性未確認のため通電は禁止しています。VMを接続しないでください。

## まずモックで試す

1. `http://127.0.0.1:18181/ouchi-colon/?motor=1` を開き「モックを接続」。
2. 「Atomから読み込む」でモックの12パターンを取得。前後は200ms、旋回は未校正0msです。
3. 4項目を確認し「1回の試験を許可」。前進25%などの「1回実行」を押します。200msで停止・許可解除されます。
4. 時間を編集して「このPCに保存」はブラウザ内だけ。「Atomへパターンを書き込む」は接続先へ保存・読戻しします。モック時は実機が変わらないことを表示します。

接続中の定期通信では読取り・保存ボタンは無効になりません。押すと「読み込み中…」などの表示で、進行中の通信が終わるのを待って処理します。処理中の連打は不要です。以前の画面でボタンが点滅し「接続して通信完了を待ってください」が出る場合はCtrl+Shift+Rで再読み込みし、BLEへ再接続してください。この修正ではファームの再書込みは必要ありません。

## USB-Cでファームウェアを導入（ユーザー操作）

PCのChrome / Edge、localhostまたはHTTPS、データ通信対応ケーブルが必要です。iPhone SafariのUSB書込み・BLE操作には対応しません。アプリ内ブラウザで非対応なら同じURLをPCのChrome / Edgeで開いてください。

1. USB・モーター電源を切り、VMと外付け回路を外します。既存ファームのソースまたは復元方法を確保します。今回の書込みは既存のAtom内ファームを置き換えます。OuchiColon Web側の会話・表情は維持しますが、既存Atom側機能を保持する保証はありません。
2. AtomS3をPCへUSB-C接続。公式手順に従いリセットを約2秒長押し、内部の緑LED点灯後に離してダウンロードモードへ入れます。
3. USB欄の3項目を確認し「USBを選んで接続（リセット）」。チップがESP32-S3、フラッシュ8MB以上か確認します。この識別だけではAtomS3 C123基板の保証にならないため現物確認も必要です。
4. 「既存内容をバックアップ（8MB）」でPCへ保管。機器固有設定を含む可能性があるので公開しないでください。復元には対応ツールと対象チップ・配置の確認が必要です。
5. バックアップまたは復元確認にチェックし「信号試験ファーム1.1を書き込む」。同梱4ファイルをSHA-256確認後、指定領域のみ書込み、実機MD5を照合します。全チップ消去・自動再起動はしません。NVSの空隙を避けていますが既存アプリの互換性は保証しません。
6. 完了表示後「書込み確認後に再起動」。USBを切断し、Motor Testの実機BLEをユーザー操作で選び `Colon-Motor-Test` へ接続。版 `colon-motor-1.1.0`、左右0、許可なしを確認します。VMは外したまま、[信号試験手順](hardware-test.md)へ進みます。

USBケーブルはファーム導入用です。導入後の制御と12パターン保存はBLE経由です。旧Notif v5 / notifnano / notif v10や表示アプリ用ファームではこのモーターサービスを利用できません。

### 接続ボタンが押せない・ツールの読込みに失敗するとき

USB欄に準備状況と、未確認の項目数を表示します。書込みツールの準備と3項目の現物確認が終わると接続ボタンが使えます。ケーブルを挿しただけで自動接続はしません。Web Serial未対応と表示された場合はPCのChrome / Edgeで開きます。

以前の開発画面で `Failed to fetch dynamically imported module .../.vite/deps/esptool-js.js` が出る場合は、修正済みサーバーでCtrl+Shift+Rを押して再読み込みしてください。USB機器の故障を表すエラーではなく、書込みツールの配信エラーです。公式の単一ファイル版をページ表示時に準備し、準備完了後のクリックで直接USB選択を呼ぶ方式に修正しました。この準備だけではUSB機器へアクセスしません。

## 12パターン

| 種類 | 出力 | 時間 |
|---|---|---|
| 前進・後進、各3枠 | 25 / 50 / 75%固定 | 初期200ms、50〜500msまたは0で無効 |
| 右・左、各15 / 30 / 45° | 各枠25 / 50 / 75%を選択 | 初期0msで禁止。実測校正後に50〜500ms |

角度センサーやエンコーダは実装していません。「30°」は時間を校正して付ける名前です。床、負荷、電池、出力が変われば実角度も変わります。500msで届かなくても自動で複数パルスに分割しません。正確な角度停止には別のセンサーと制御設計が必要です。

左右の前進方向は単体試験で確認し、左右反転設定を使います。出力%はPWMデューティであり、印加電圧の安全制限ではありません。適合確認前に校正のためのモーター通電も行わないでください。

## OuchiColonの表情と連動

1. 顔画面 `?debug=1` の「OuchiColonモーター連動（初期OFF）」を開きます。
   Motor Test内の「OuchiColonの表情・動作と連動する」を開き、「顔画面でモーター連動を設定する →」を押すと、現在の接続を終了し、同じタブで連動パネルを開いた顔画面へ移動します。顔画面の初期接続はモックなので、実機を使う場合はそこで実機BLEを選び直してください。独立テスト画面には表情の割当欄を表示しません。
2. 初期のモックで接続し、パターンを読み込みます。独立Motor Test画面を別タブで裏に隠して使う方式ではありません。顔画面内の同じページで制御します。
3. 「OuchiColonの表情・動作と連動する」を開き、例：HAPPY → 前進25%。IDLE / HAPPY / TALK / THINK / SURPRISE / SAD / SLEEP / SEARCHに割当できます。会話本文や個人情報は使いません。
4. 連動ON、安全確認4項目、最後に「信号連動を1回だけ許可」。次の対応表情イベントで1動作だけ実行し、パルス上限で停止・許可解除します。
5. デバッグキー2でHAPPYを試せます。自動の表情変化もイベントになるため、どのイベントに割り当てたか確認してから許可してください。初期は全て「連動なし」です。

停止・切断・非表示・フォーカス喪失では許可を解除します。連動ONでも自動再許可・自動連続走行はしません。実機通電での会話連動は、電源と停止波形の検証を終えてから別途受入れが必要です。

## 再ビルド

```sh
npm ci
npm run build
cd firmware/motor-test
pio run
cd ../..
# ビルドに使ったPlatformIO coreの絶対パスをPLATFORMIO_CORE_DIRに指定
node scripts/package-motor-firmware.mjs
```

同梱バイナリは `public/firmware/manifest.json` にハッシュと書込み先を記録しています。`MOTOR_ALLOW_POWERED_TESTS=0` のビルドだけを配布パッケージにできます。
