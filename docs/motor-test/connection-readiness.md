# 接続準備と停止応答の見直し（2026-11-09）

画像の「BLE接続済み・操作準備中・停止理由connected-disarmed」を受け、接続開始と停止処理を調査しました。実機の現象そのものの再現・測定はしていません。

初期状態の読取り完了前にconnected=trueとしていたため、遅いBLE読取り中に定期通信や画面側の再起動検知が先に走る余地がありました。初期状態とシーケンスを取得してから接続完了とするように変更しました。準備中に切断した場合も、後から届いた応答で接続済みに戻しません。画面の接続状態変化の記録は停止要求より先に更新します。

指令処理は以前、各読取りに2秒の上限があり、受付待ちを最大12回繰り返せました。指令全体（事前読取り・書込み・受付読取り）で2秒を上限としました。STOP/DISARM/ESTOPは本体のnonce更新と停止理由、出力0を確認します。受付が返らない場合は停止未確認として切断し、操作待ちのまま残しません。通常指令の失敗時は停止要求を送り、その停止にも上限を適用します。処理中の画面は「停止応答を確認中」「操作・設定の応答を確認中」など、待っている内容を表示します。

電池3V、出力100%、W/S最大500ms、左右共通15/30/45/90°=2/4/6/12秒、A10後進0.5秒→停止1秒→前進0.5秒は変更していません。本体1.8.0と独立した350ms心拍停止も変更せず、再書込みは不要です。

Web319件、TypeScript/Viteビルド、Chromeの疑似BLE・モックによるWASD/停止/番号動作/再接続/レスポンシブ試験が成功しました。追加テストは、初期読取り中の定期通信抑止、途中切断の維持、STOP応答なし時に2秒程度で切断して処理中表示を解除するケースです。実機の書込み・モーター操作はしていません。
