# 実機試験手順（未実施）

この手順は今後の確認用です。今回、書き込み・モーター通電は実施していません。配線変更は全電源OFFで行います。以下の実機項目は全て未確認で、自動テストの成功を代用しません。

## Phase 1・2：コード／モック

READMEのビルド・テストを実行。モックで初期停止、確認前の操作禁止、左右個別、反転、最大パルス、緊急停止、解除後の再ARM、画面非表示／再接続、JSON／CSVを確認します。物理モーターは接続不要です。

## Phase 3：AtomS3だけ（モーター電源OFF）

1. 実物がAtomS3 C123であること、現在のプログラムのバックアップ／復元方法を確認。
2. ユーザーが内容をレビューし、書き込みを明示的に承認する。初期の診断用ビルドを使用。
3. VMは物理的に切断。モーターも未接続にする。
4. AtomS3へだけUSB給電。シリアル115200bpsでWi-Fi情報を確認。
5. PC／スマートフォンをそのWi-Fiにつなぎ `http://192.168.4.1/` を開く。画面で接続先をAtomS3へ切り替えて接続。
6. ファームウェア、起動回数、再起動理由、ハートビート、GPIO初期化、出力ビルド無効を確認。
7. 再起動／接続解除／通信遮断後にARMが戻らないことを確認。GPIOはLOWを実測。

初期ビルドは診断専用なので、正転／逆転の信号を出す試験へは進みません。

## Phase 4：DRV8835制御信号だけ

1. 先にVM OFF・モーター未接続を再確認。共通GNDとDC-DCの入出力関係が不明なら接続を止める。
2. G5〜8／VCC 3.3V／MODE=GND／GNDを照合。
3. ユーザー承認後に、出力のみ有効な信号試験ビルドへ進む。`COLON_POWER_QUALIFIED`は0のまま。
4. Phase 3／4で確認欄を満たし、左右を一つずつ短時間試験。測定器で入力信号を確認。
5. 指を離す、最大パルス、通信断、非表示、緊急停止、正逆切替のLOW区間をロジックアナライザー等で測定。
6. ロジックの停止指令と、実際にGPIOがLOWになる時間を分けて記録する。

## Phase 5：モーター単体（現在は進行不可）

開始条件は、VMの**実測**・極性・負荷時電圧、1.5Vにおけるドライバー基板の適合、モーター定格／始動・拘束電流、電源・配線・放熱の確認、物理遮断の用意です。現状は未達です。PWMのデューティ比で過電圧を安全化したとは判断しません。

条件を満たしてから、ユーザーが通電を承認し、電源適合を確認したビルドを検討します。キャタピラは浮かせ、片方のみ、初期100msの短パルスから。始動しなくても、そのまま電圧を上げたり長く通電したりせず停止して原因を確認します。

## Phase 6：走行（Phase 5完了後）

左右それぞれの前進方向を記録し、必要なら反転設定。浮かせた状態で前後／旋回、停止、切断、緊急停止を確認してから、障害物のない限定した範囲で低速試験。STOPは空転であり、停止距離・キャタピラの慣性・転倒を実物で評価します。
