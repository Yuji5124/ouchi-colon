# 本体単独テスト1.2：1.5V想定・未測定

2026-11-05のユーザー指定により、DC-DCを実測せず1.5V想定で本体を試すための、明示的な実験モードを追加しました。推奨電圧と実際の出力が一致することを確認したモードではありません。ドライバ・モーター・DC-DCの適合性、電流容量、GND関係などの未解決事項は残ります。短いパルスやPWMで過電圧・配線不良を安全化できるとは扱いません。

## ファームの違い

| 項目 | 信号試験1.1 | 本体単独1.2 |
|---|---|---|
| モーター電源 | VMを外す | 1.5V想定の限定試験。実測未確認 |
| 制御 | 既存の信号試験 | 左または右1個ずつ |
| 出力 | 信号試験の設定範囲 | 25 / 50 / 75%（ファーム上限75%） |
| 1回の時間 | 最大500ms | 50〜100ms。ファームのハード上限100ms |
| 周波数 | 100〜20000Hz | 1000Hz固定 |
| 両輪走行・パターン・表情連動 | VMなし信号確認 | 使用不可 |
| 電源適合フラグ | false | falseのまま。想定を適合確認へ昇格しない |

起動時停止、切断停止、心拍期限350ms、最大パルス、緊急停止ラッチ、停止後100ms待機、操作ごとの再許可は維持します。単独版では通常ARM・信号ARMによる制限回避も拒否します。起動時やリセット中のGPIO実波形、実際の停止時間・惰性は未測定です。

## 1. USBで単独版を導入する

1. モーター電源VMを切り、USBと外付け回路を外します。配線変更は無通電で行います。
2. PCへAtomS3 C123だけをUSB接続。必要なら公式の長押し操作で書込みモードへ入れます。
3. Motor TestのUSB欄で「書き込むファーム」を **本体単独1.2（1.5V想定・未測定／片側100ms）** に変更。
4. 確認項目、復元手段・バックアップを確認して、ユーザー自身の操作で書き込みます。実装作業では実機の書込み・通電を代行していません。
5. 書込みとMD5照合の完了後に再起動し、アプリでUSB通信を切断。USBケーブルは給電用に挿したままで構いません。
6. 実機BLEで `Colon-Motor-Test` へ接続。見つからなければ検索をキャンセルし、VMを外したまま本体を短くリセットして再検索します。
7. **colon-motor-1.2.0、左右0%、駆動禁止** を確認。単独モード・Phase 5・初期25%・100msへ切り替わります。許可は自動で付きません。本体単独モードではパターン・連動の欄を隠し、単体テストを優先表示します。

従来の1.1信号試験版では単独通電モードを許可できません。今回はファーム切替が必要です。既存12パターンのNVS領域を避ける分割書込みですが、バックアップ・復元確認は必要です。

## 2. 本体へ配線する

USB・VMを切ってから、基板の端子印字を確認して接続します。

| 接続元 | 接続先 |
|---|---|
| AtomS3 G5 / G6 | AIN1 / AIN2 |
| AtomS3 G7 / G8 | BIN1 / BIN2 |
| AtomS3 3V3 | DRV8835 VCC（論理電源） |
| AtomS3 GND | DRV8835 GND / MODE |
| DC-DC OUT− | 共通GND |
| DC-DC OUT+ | 物理スイッチ経由でVM |
| AOUT1 / AOUT2 | 左モーター |
| BOUT1 / BOUT2 | 右モーター |

基板の向きとピン番号は[正式配線表](hardware.md)を照合します。GPIOとVCCは3.3Vロジック、VMとは別です。USBの5VをVMへ直結しません。DC-DCの入出力GND関係と極性は現物で確認します。最初は左モーターだけ接続し、右の確認へ進むときも電源を切ってから変更できます。

## 3. 片側ずつ短時間で確認する

1. キャタピラを浮かせ、周囲とVMの物理遮断手段を確認。VMスイッチを切ったままUSB給電し、BLE接続と左右0%を確認します。
2. 想定1.5Vのモーター電源を接続する操作はユーザーが行います。設定値と実測値は区別し、未測定欄は空欄のままにします。
3. 画面の4項目を現物に基づいて確認。最後の項目は「1.5Vは想定・未測定で、部品適合も未確認の短時間試験と理解した」です。「VMを外した」と偽って信号試験を使う必要はありません。
4. 「確認して1回の試験を許可」→「左 正転」を押したままにします。短いクリックは、通信が終わる前の指離しで停止要求になる場合があります。押している間だけ、最大100msで停止・許可解除します。離す操作・緊急停止も停止要求になります。
5. 初期は25%。短時間・低出力では回転が見えない場合があります。回らない場合も電圧を上げず、異音・発熱・引っ掛かり・電源消失などを確認します。異常時はVMを物理遮断し、繰り返し通電しません。
6. 異常がなく必要な場合は、停止を確認して出力50 / 75%を選び、再許可して1回ずつ確認します。ソフトスタートのため表示どおりの出力に達するまで時間がかかります。
7. VMを切って停止・発熱を確認し、右側も同様に確認します。回転方向が逆の場合は左右反転設定を使い、変更後は再許可します。

通常走行や表情連動へはこのファームのまま進めません。連動は今回保留です。電源や部品の適合性を確認してから、別の受入れ試験で扱います。

## 記録と再ビルド

ログには `assumedMotorV:1.5`、`provenance.assumedMotorV:"user-assumption"`、`measuredV:null`、`powerQualified:false` を記録します。手入力実測値がある場合だけuser-measuredです。CSVも試験モード・想定VM・未適合を区別します。

```sh
pio run -d firmware/motor-test -e atoms3-single-test
# PLATFORMIO_CORE_DIRをビルド環境の絶対パスへ設定してから実行
node scripts/package-motor-firmware.mjs --single
```

配布先は `public/firmware/experimental/`。通常信号版の配布ファイルは維持します。選択前に自動で単独版へ切り替えたり、書き込んだりはしません。

参考：[TI DRV8835](https://www.ti.com/lit/ds/symlink/drv8835.pdf)はVMとVCCを別に規定しています。[タミヤ70227](https://www.tamiya.com/japan/products/70227/index.html)の単3電池1本という構成は、手元のDC-DC出力の実測・基板適合の確認にはなりません。
