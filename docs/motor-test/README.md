# Colon AtomS3 Motor Control 1.8.0

電池3V・出力100%・時間制御。操作前の許可ボタンや測定値の入力はありません。

1. USB欄から走行プログラム1.8.0を書き込みます。書込み中はVMと外付け回路を外します。
2. 通常起動してアプリでAtomS3にBLE接続します。
3. W/Sは押している間だけ前後進し、離すか最大時間（50〜500ms）で停止。A/Dは校正済みの左/右90°を1回実行します。
4. 旋回は左右共通で15°=2秒、30°=4秒、45°=6秒、90°=12秒。片側の時間編集は反対側にも反映されます。
5. No. 1=前進100%・1秒、No. 2=後進100%・1秒。No. 3〜8=左右15/30/45°、No. 9=右90°、No. 10=左90°を時間で校正してAtomへ保存します。
6. A01〜A17の番号付き動作で組み合わせを試し、Colonの顔画面内で言葉・表情・顔方向に連動できます。[番号一覧と実機で試す順番](actions.md)

起動・再接続だけでは動きません。電池3Vはユーザー指定の設定で、本体に電圧・電流・回転角の測定機能はありません。停止・通信断停止は本体側でも監視します。複数ステップの順序はブラウザが管理し、ブラウザ非表示・停止で残りを取り消します。

```sh
npm ci
npm run dev -- --configLoader runner --host 127.0.0.1 --port 18181
```

[操作画面](http://127.0.0.1:18181/ouchi-colon/?motor=1) / [Colon連動](http://127.0.0.1:18181/ouchi-colon/?debug=1&motorLink=1) / [A01〜A17の仕様](actions.md) / [データ整合性の再確認](consistency-audit.md)

## 既存コード調査

調査対象：`Yuji5124/ouchi-colon` の `4f32a53486d82fefe0140cc2dd30b298d0b2c180`。

- Vite + TypeScript + Canvas、会話・音声・表情・顔追跡のPWA。
- 調査時点で `src/` にBLE、HTTPモーター制御、WebSocket、GPIO実装はありません。ATOM用ファームウェアもありません。
- 前の依頼で作成した別リポジトリ `colon-atom-app` はNotif v5の表示データ転送用です。提供されたNotif v5にも、この停止タイマー・モーター制御プロトコルはありません。
- 既存の `src/main.ts` に表情名の通知を追加し、非同期の入口から読み込んだ後もPWA登録できるようload完了済みの場合を補いました。会話・音声・顔追跡処理は維持しています。新しい `entry.ts` がMotor Testと従来起動を分岐します。顔画面内の任意パネルで、初期OFF・許可1回ごとの表情パターン連動を追加しました。通知は表情名だけで、会話本文を転送・保存しません。
- 既存の実機ファームウェアが提供されていないため、同じ機器上の既存BLEサービスやロボット制御との共存は未検証です。

## 通信を追加した理由

再利用できるモーター通信が既存OuchiColonにはないため、専用BLEサービスを新設しました。PCの対応Chrome / EdgeやAndroid Chromeで、HTTPSまたはlocalhostのセキュアコンテキストから利用します。iPhone Safariではモックを利用できます。

新たなWi-Fi公開サーバー、外部クラウド、LAN上の無認証モーターAPIは追加していません。

## 実装した制御

- A / B独立、論理正転・逆転、左右方向反転設定。方向反転設定は実機の前進方向の確認用です。
- 左右0〜100%の速度、100〜20000HzのPWM、50〜500msの最大駆動時間（既定200ms）。
- ソフトスタート（0→100%に約100ms）。常に停止を挟み、停止後100msの待機と再許可を必要とします。
- 停止はIN/INの00、Hi-Zによる空転停止です。11のブレーキや機械的ロックは安全停止の代わりに使いません。軸が慣性で回ることはあります。
- 起動時・初期化不備・切断・HBの350ms途絶・最大パルス到達・不正コマンド・モード変更・画面非表示・指離しで停止または停止要求。
- ファームの安全処理は独立した5ms周期のFreeRTOSタスク。ブラウザやBLEコールバックの継続実行を必要としません。BLE処理との間は容量制限したキューで接続し、処理過多でも停止を優先します。
- 緊急停止はラッチ。解除しても駆動許可は復活しません。
- ブート / 接続 / 停止でセッションnonceを更新し、旧フレーム・再送・古い操作の復活を拒否。心拍は駆動パルスを延長しません。

## ファームウェアの重要な制限

`firmware/motor-test` は **独立した実機信号試験用ターゲット** です。既存のATOMファームウェアへ上書きして機能を維持することは保証しません。既存実機ファームウェアを入手した後、`MotorCore.h` と通信処理を組み込んでGPIO・PWMリソース・BLE共存を確認する必要があります。1.1.1 / 1.2.1から本体液晶の状態表示を追加しました。既存ロボット機能は、この独立ターゲットには含めていません。

配布構成は `MOTOR_ALLOW_POWERED_TESTS=0`。モーター通電はファーム側でも拒否します。GPIO試験は、VMを物理的に外したという明示確認をした場合に限ります。ソフトではVMが本当に外れているか測定できません。

電源と部品の適合性が確認された場合だけ、レビューを経て別の通電試験ビルドを用意します。1.5Vの設定値を入力したり、Webチェックを付けたりするだけでは、このコンパイル時ロックは解除されません。

## 診断・測定値

ファーム値：稼働時間、NVSへの起動回数記録、ESPの再起動理由、制御状態、停止理由、ハートビート経過時間。NVS書込みができないと起動回数はnullです。起動回数はこのファームのNVS名前空間のカウントで、初期化・消去時にリセットされます。bootIdの変化でも再起動を検出します。

手入力：DC-DC設定（初期1.5V）、実測、消灯までの時間、消灯後のUSB出力、駆動中の電源状態、発熱、測定日時、結果。手入力実測値も「user-measured」としてセンサー値と区別します。

取得不可：SMARTCOBY内部電圧、DC-DC入力電圧・出力電圧の自動測定、実電流、低負荷停止の内部判定。UIは未測定 / 取得不可を表示します。表示消灯からUSB停止を推定しません。再起動理由がbrownoutでも、DC-DCやSMARTCOBYの原因を特定したことにはなりません。

ログはメモリ内最大1000件。JSON / CSVには日時、段階、情報源、接続、稼働時間、再起動理由、操作、PWM、停止理由、設定・実測電圧、測定日時、電源状態、結果・エラーを含めます。JSONの `provenance` が設定・手動実測・未測定・モック・ファームを区別します。再読込み前にエクスポートしてください。
