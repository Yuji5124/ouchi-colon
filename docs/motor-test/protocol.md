# 1.7.0追加仕様

既存のBLEサービス・20byteフレームを継続使用します。走行プログラム1.7.0のpatternsVersionは5で、No. 1〜10を扱います。従来のNo. 1〜8にNo. 9=右90°、No. 10=左90°（各0=未校正、50〜2000ms）を追加します。NVSはpatterns-v5、旧v4/v3を移行します。

MOVEはbyte16=4で50〜500ms、byte16=5でA動作の1ステップ50〜2000msです。PATTERNは保存済みスロットの時間を使用するため、mode4のフレームでも前後進1000ms・90°最大2000msになります。byte17の設定時間とPATTERNの保存時間は別です。byte15=0で、1.7.0以外へmode5を送りません。100%固定、心拍350ms、方向変更前100ms停止、切断停止、再接続時停止を維持します。A01〜A17自体は新しいAtomコマンドではなく、既存MOVE/STOP/HEARTBEATと基本校正値で構成するブラウザの順序定義です。

詳細は [A01〜A17](actions.md)。以下は従来仕様の記録です。

# 現在の直接操作（ファーム1.6.1）

BLEサービスと20バイトフレームは下記と共通です。パターン形式はpatternsVersion:4、No. 1〜8のワイヤ上のインデックスは0〜7です。

直接操作ではMOVEまたはPATTERNのbyte 15を0、byte 16を4にします。このモードは動作ボタンからの明示的な操作を表します。電源電圧や配線の確認済みフラグは立てません。powerQualifiedもfalseのままです。旧版ファームはこのモードを受け付けません。

クライアントは必要な停止待機の後、設定を含むMOVEまたはPATTERNを1フレームで送ります。継続中のHEARTBEATは別途送信します。STOP/ESTOPは待機中の処理を取り消し、nonceを更新します。手動許可ボタンは使用しません。

# Motor Test BLE v1

専用サービス：`b4c00001-70f0-4c21-a560-cc0100000001`

書込み：`b4c00002-70f0-4c21-a560-cc0100000001`（Write with response）

状態読取り：`b4c00003-70f0-4c21-a560-cc0100000001`（UTF-8 JSON、最大512bytes）

v1.1パターン読取り：`b4c00004-70f0-4c21-a560-cc0100000001`（JSON、最大256bytes）。状態の `patternsVersion:1` で対応を確認します。

20byte固定フレーム、数値はlittle-endian。標準MTUでもコマンドを分割しません。状態JSONは長いCharacteristic Readを使用します。通知を駆動許可の根拠にはしていません。

| byte | 内容 |
|---|---|
| 0 | protocol=1 |
| 1 | ARM=1 / DISARM=2 / MOVE=3 / STOP=4 / HEARTBEAT=5 / CONFIG=6 / ESTOP=7 / RESET_ESTOP=8 / PATTERN=9 / SAVE_PATTERN=10 |
| 2〜5 | nonce（状態から取得） |
| 6〜9 | 単調増加sequence |
| 10 | 左の符号付き速度 −100〜100 |
| 11 | 右の符号付き速度 −100〜100 |
| 12〜13 | PWM Hz（100〜20000） |
| 14 | CONFIGの方向反転bit0=左、bit1=右 |
| 15 | ARMの安全確認bit0〜3全て=1（15） |
| 16 | signalOnly=1 / qualified-powered=0 / 単独実験=2（1.2単独版のみ） |
| 17〜18 | CONFIGの最大パルスms（50〜500） |
| 19 | 予約=0 |

PATTERNではbyte10を0〜11のスロット番号として使います。SAVE_PATTERNではbyte10がスロット、byte11が出力25/50/75、byte17〜18が時間0（無効）または50〜500ms。保存は未許可時のみ、実行は通常と同じARM・心拍・停止条件を必要とします。スロット順は前進25/50/75、後進25/50/75、右15/30/45、左15/30/45。左右反転はCONFIGが適用されます。

読取りJSONは `{ "version":1, "build":"COLON_POWER_LOCK=0", "slots":[[25,200], ...] }`。保存はNVSの `colon-motor/patterns` に版1＋12×3byte。Webは12枠を書き込み、読戻し一致を確認します。途中失敗は一部保存として表示し、再読込みが必要です。これらはNotif v5 / notifnano / notif v10との互換コマンドではありません。

左単体・右単体・走行は1つのMOVEで左右の符号付き値を同時指定。無線上に独立GPIOを順番に書き込む方式は使いません。CONFIGは許可解除中のみ。STOP / DISARM / ESTOPは古いnonceでも停止を優先します。他はnonceとseqを確認。STOPは許可を解除しnonceを更新するため、処理待ちの古いMOVEは再開できません。

HEARTBEATは接続中に約120ms間隔で送ります。ARM中に350ms以上途絶すると停止・許可解除。未許可中の心拍は電源診断の通信生存確認に使い、許可を復活させません。MOVEによる単発パルスは心拍でも延長できません。ブラウザが送信失敗やタイムアウトを検出すると停止要求し、停止応答も確認できなければ接続を破棄します。再接続やページ再表示で再許可しません。

ブラウザ側はGATT操作を直列に実行します。パターン読取り・一括保存・設定と許可は現在の通信の完了後に枠を予約し、定期通信を間へ入れません。未許可中の一括保存では心拍診断が一時停止し、保存後に再開します。停止・切断は待機処理を取り消し、残りの保存や許可を再開しません。MOVE / PATTERNは待ち行列に入れません。ファーム側の350ms / 最大500ms期限は変更しません。

このテストサービスに暗号学的な操作者認証は追加していません。近傍BLE接続、ペアリング、物理VM遮断、コンパイル時通電禁止を運用境界とします。有人・有人近傍の実用ロボットや公開空間での連続運転には別途認証・インターロック設計が必要です。

単独版1.2は状態のsingleTest:trueで識別し、powerQualified:falseのままです。ARM byte16=2だけを許可し、通常・信号ARMを拒否します。CONFIGは1000Hz・50〜100ms、MOVEは片側のみ・絶対値75以下、PATTERNは拒否。tick側にも100ms上限を持ちます。新しい制限は実ファームが強制します。通常1.1の既存期限は維持します。
