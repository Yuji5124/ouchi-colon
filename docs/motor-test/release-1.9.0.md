# Colon Motor 1.9.0 — Notif保存版（2026-11-09）

利用者の「45°用の6秒で実際に360°回った」という観察を基準に、時間を1/8へ修正しました。右・左に共通で、15°=250ms、30°=500ms、45°=750ms、90°=1500msです。A01〜A06、A07の顔方向、A11/A12、ラジコンA/D・A15/A16、基本動作No.3〜10は同じ保存値を使います。前後進各1秒、A07前進2秒、A08の左右各1秒、A09の後前各1秒、A10の後0.5秒→休止1秒→前0.5秒は維持します。時間指定の喜び動作を角度へ変換していません。

この比率から算出した値の実角度は未確認です。短時間の始動・床面・電池状態による差を実機で校正してください。電池3V・出力100%設定です。

## 途中停止への対応

1. 1.9.0の本体心拍監視を350msから1000msへ変更。旧1.8.0以前は350msのままです。
2. 1.9.0のWebは心拍を優先して80ms間隔を目標に送信し、状態読取りは500ms間隔へ減らします。各通信は直列で、実際の間隔にはHTTP/GATT待ち時間が加わります。
3. 250msの動作が初回応答より先に完了しても、ファームの動作受付番号`moveSeq`と正常終了理由で確認します。正常完了を受付失敗と誤判定して余分なSTOPを送る処理を防ぎます。別指令の受付番号・手動停止・心拍停止は正常完了扱いにしません。
4. Windows読取りは`use_cached=False`を明示します。これはBleakの元の既定値でもあり、キャッシュが今回の原因だったと断定していません。[公式仕様](https://bleak.readthedocs.io/en/stable/backends/windows.html)。

停止ボタン、緊急停止、非表示、フォーカス喪失、キー解放（前後進）、切断、設定時間の終了は引き続き停止条件です。1秒以上心拍が届かない場合も停止し、自動再始動しません。停止要求が届かないときは最後の心拍受付から最大約1秒（本体制御周期が加算）で停止します。サーバーが独自に心拍を作って動作を延長する機能はありません。通信遅延が1秒を超える場合や電気的な問題まで解消する保証はありません。今回の実機の停止原因は未確定です。

## 保存と復元

- 現行ソフト・ファーム：1.9.0、パターン形式7、PCキー`colon-motor-patterns-v7`、本体NVSキー`patterns-v7`。
- 旧v6設定は残し、1.9.0では読み込みません。初回は修正済み初期値を使います。v7で保存した値は再起動後も保持します。
- `public/motor-release-1.9.0.json`に通信モード・角度・A10・心拍上限を固定して保存します。
- USB欄の「Notif保存版1.9.0に戻す」は`public/firmware/notif-1.9.0/manifest.json`と対応4ファイルを読み込み、SHA-256と実機MD5を照合します。将来の既定ファームとは独立した保存先です。書込みはユーザー操作で行い、自動書込みはしません。
- GitHubの両リポジトリに`colon-motor-1.9.0-notif`タグを保存します。今後のBLE版からソフト全体を戻す場合は、両方をこのタグのソースへ戻し、専用環境を準備してビルド・サーバー起動してください。ローカルの復元用ZIPにもサーバーとビルド済み画面を保存します。

## 接続方式の切替

Notif： http://localhost:18180/ouchi-colon/?motor=1&transport=notif

直接BLE： http://localhost:18180/ouchi-colon/?motor=1&transport=ble

接続中の画面を切断してから切り替えます。同じ1.9.0ファームで両方式に対応し、接続方式だけの変更で再書込みは不要です。URLの明示指定をサーバーの既定値より優先します。選択欄と「Notif接続に戻る」リンクから戻せます。両方式ともPC〜Atom間の無線はBLEで、USBは書込みと給電用です。

1.8.0から角度・監視時間・受付番号を更新するには、VMを外した状態でUSB欄から1.9.0を書き込み、通常起動後に本体版と共通時間を確認してください。新しい画面では、旧本体の角度設定を誤実行しないよう、1.9.0以外は識別と更新を案内し走行操作を無効にします。実装作業では実機への書込み・検索・接続・通電は行っていません。
